# Gesture Bridge

Перенос содержимого между устройствами жестом. Сжал кулак перед одним
устройством — показал раскрытую ладонь перед другим, и содержимое
переехало. Ссылки, файлы, выделенный текст, картинки из буфера обмена.

Ничего не открывается, не выбирается в меню и не перетаскивается мышью:
захват и приём — это два жеста рукой в воздухе.

## Что умеет

### Что можно захватить

Агент перебирает способы от самого точного к самому общему и берёт
первое, что нашлось. Первые четыре шага не имеют побочных эффектов:

| Что в фокусе на ПК | Что улетит | Как добыто |
|---|---|---|
| браузер | ссылка активной вкладки | UI Automation, адресная строка |
| проводник | выделенные файлы, полными путями | Shell COM |
| любое приложение с выделением | выделенный текст | UI Automation, `TextPattern` |
| — | что лежит в буфере: файлы, текст, картинка | WinAPI, все форматы буфера |
| ничего из этого не дало | Ctrl+C и смотрим, что появилось | эмуляция нажатия |

Последний шаг — резерв для приложений, которые не отдают выделение через
UI Automation, и для выделенной области в графических редакторах: её
нельзя получить ничем другим. Буфер при этом сохраняется и возвращается
(только текст — пересоздать произвольный набор форматов средствами
WinAPI нельзя). Отключается флагом `--no-deep`.

Посмотреть, что улетит прямо сейчас, не делая жеста:

```bash
python agent/main.py --what
```

### Куда это приедет

| Тип | На ПК | На телефоне |
|---|---|---|
| ссылка | откроется в браузере | откроется, либо кнопка «Открыть» |
| текст | ляжет в буфер обмена | покажется с кнопкой «Скопировать» |
| файлы | скачаются в «Загрузки», откроется проводник с выделенным файлом | скачаются браузером |

Ссылку на файл человек не видит — приёмник скачивает сам. Браузер на
телефоне не даёт ни открыть вкладку, ни записать буфер без явного
касания (жест рукой касанием не считается), поэтому там остаётся одна
кнопка. На ПК таких ограничений нет, всё происходит само.

### Направления

| Откуда | Захват | Сброс |
|---|---|---|
| ПК → телефон | кулак в веб-камеру ПК | ладонь во фронталку телефона |
| ПК → ПК | кулак в веб-камеру одного | ладонь в веб-камеру другого |
| телефон → ПК | «Поделиться» → Gesture Bridge | ладонь в веб-камеру ПК |

С телефона захват идёт через системное меню «Поделиться», а не жестом:
когда ты отправляешь с телефона, ты держишь его в руке, и показывать
кулак собственной фронтальной камере неудобно. В стенд-режиме (телефон
на зарядке, приложение открыто) камера работает постоянно, и это
ограничение снимается.

### Если ладонь не показали

Посылка не теряется. Через 15 секунд она перестаёт «лететь» и падает в
висящую очередь, откуда её можно забрать тапом по списку в приёмнике.
Висит час.

## Как это работает

Три части, каждая запускается отдельно:

| Часть | Где живёт | Что делает |
|---|---|---|
| `broker/` | сервер (или тот же ПК) | WebSocket, аукцион жестов, очередь посылок, хранилище файлов, раздача приёмника |
| `agent/` | Windows-ПК | камера, жесты, захват содержимого, оверлей, приём |
| `receiver/` | телефон, в браузере | ладонь по фронталке, приём, отправка через «Поделиться» |

### Решения, которые стоит понимать

**Камера на телефоне выключена.** Она поднимается, только когда брокер
сказал «для тебя есть посылка», и гаснет через 15 секунд. Поэтому
батарея не страдает и ложных срабатываний почти нет. Постоянную работу
включает кнопка «стенд» — для телефона на зарядке.

**Жест — это ставка, а не приказ.** Устройство, увидевшее жест, не
действует само: оно сообщает брокеру свой счёт, брокер ждёт 250 мс,
собирает ставки всех устройств и объявляет одного победителя. Счёт
складывается из площади кисти в кадре (ближе рука — выше балл), свежести
ввода и уверенности распознавания. Без этого при трёх устройствах одну
показанную ладонь увидели бы сразу несколько камер.

**Захват двухфазный.** Увидев кулак, агент не снимает содержимое сразу —
сначала выигрывает аукцион и только потом берёт. Иначе проигравшие
устройства успевали бы нажать Ctrl+C в чужом окне и залить файлы
впустую.

**Отправитель не может быть приёмником.** Сжав кулак, человек разжимает
руку, опуская её, — и собственная камера видит раскрытую ладонь. Свои
посылки отсеиваются ещё до аукциона: иначе отправитель с самой близкой к
камере рукой выигрывал бы торг и забирал посылку обратно, заодно
блокируя устройство, которому она предназначалась.

**Ладонь берёт верх стека.** Выбрать источник жестом нельзя — в жесте
просто нет такой информации. Поэтому ладонь всегда забирает самую свежую
посылку, а оверлей на ПК показывает, что именно она заберёт, ещё до того
как ты её показал. Если грузов несколько, остальные падают в висящую
очередь и берутся тапом.

**Удержание держится на двух порогах.** Уверенность модели всё время
дышит: ладонь, которую камера уверенно видит, даёт не ровные 0.8, а
разброс вокруг. Требование непрерывной серии кадров выше одного порога
обнуляет отсчёт на каждом провале — на веб-камере это почти незаметно,
на фронтальной камере телефона ломает распознавание полностью. Поэтому
войти в удержание труднее (`ENTER_CONFIDENCE`), чем в нём остаться
(`STAY_CONFIDENCE`), а короткая потеря руки прощается (`LOST_GRACE`). Но
сработать, пока руки в кадре нет, нельзя (`SEEN_RECENTLY`): иначе
показанная на мгновение ладонь досчитывалась бы до срабатывания уже
после того, как руку опустили. В ставку уходит лучшая уверенность и
самая крупная рука за удержание, а не последний кадр.

**Файлы не ходят в протоколе.** Отправитель заливает их брокеру и
получает идентификатор, посылка несёт только метаданные, приёмник качает
по идентификатору. Так посылка остаётся маленьким JSON, а отправитель
может уйти сразу после захвата: файл уже у брокера, и висящая очередь
работает для файлов так же, как для ссылок.

**Распознаёт готовая модель.** MediaPipe Gesture Recognizer: `Closed_Fist`
и `Open_Palm` — две из её встроенных категорий, обучать ничего не нужно.

## Установка

### Требования

| Где | Что нужно |
|---|---|
| ПК | Windows 10/11, Python 3.10+, веб-камера |
| Сервер | Linux с systemd, Python 3.10+, Tailscale |
| Телефон | Android с Chrome, Tailscale |

Сервер не обязателен: брокер можно запустить и на самом ПК. Но тогда
телефон достанет его только в домашней сети, а ПК придётся держать
включённым.

> **Важно: не клади проект в глубокий путь.** У Windows лимит в 260
> символов на путь, а у mediapipe очень глубокая структура каталогов. В
> длинном пути пакет установится, но не заимпортируется — с невнятной
> ошибкой про отсутствующий модуль. `D:\Projects\gesture-bridge` —
> нормально.

### Шаг 1. Зависимости на ПК

```bash
python -m venv .venv
```

```bash
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Ставятся mediapipe, opencv, aiohttp, uiautomation и qrcode — около 200 МБ.

Дальше в руководстве команды пишутся просто как `python`. Если не
активировать окружение (`.venv\Scripts\activate`), подставляй полный путь
`.venv\Scripts\python.exe`.

### Шаг 2. Модель распознавания

Один раз, 8 МБ:

```bash
curl -L -o models/gesture_recognizer.task https://storage.googleapis.com/mediapipe-models/gesture_recognizer/gesture_recognizer/float16/1/gesture_recognizer.task
```

### Шаг 3. Проверь, что твои жесты ловятся

До всякой настройки сети:

```bash
.venv\Scripts\python.exe agent\main.py --selftest
```

Откроется окно с камерой. Показывай кулак и ладонь, смотри на `conf` и
полоску `hold`. Выход — `q`.

Если жесты не ловятся: не держи руку вплотную к камере — слишком крупная
кисть перекрывает кадр и классификатор теряется. Оптимально, когда ладонь
занимает примерно пятую часть кадра. Свет должен падать на руку, а не в
объектив из-за спины.

### Шаг 4. Брокер на сервере

На сервер едут только `broker/`, `receiver/` и `models/` — агент
остаётся на Windows. Из зависимостей нужен один `aiohttp`, см.
`requirements-broker.txt`.

Первый раз:

```bash
.\deploy\deploy.ps1 -Target user@server -Setup
```

Скрипт скопирует код в `/opt/gesture-bridge`, создаст виртуальное
окружение, заведёт системного пользователя `gesturebridge`, сгенерирует
токен **на сервере** (чтобы он не прошёл через буфер обмена и историю
команд) и поставит systemd-юнит.

Каждое следующее обновление:

```bash
.\deploy\deploy.ps1 -Target user@server
```

Проверь, что служба поднялась:

```bash
systemctl --no-pager status gesture-bridge
```

Нужна строка `Active: active (running)` без `auto-restart`.

Токен понадобится дальше:

```bash
sudo cat /etc/gesture-bridge.env
```

### Шаг 5. HTTPS через Tailscale

Это не опция, а необходимость: браузер не даёт доступ к камере на
`http://`, а без камеры приёмник бессмыслен. Tailscale выдаёт настоящий
сертификат на имя `*.ts.net`, так что никаких предупреждений не будет.

В админке tailnet включи **MagicDNS** и **HTTPS Certificates**. Затем на
сервере:

```bash
tailscale serve --bg 8787
```

```bash
tailscale serve status
```

Должно показать `https://имя.твой-tailnet.ts.net (tailnet only)` и ниже
`proxy http://127.0.0.1:8787`. Этот адрес и есть адрес брокера.

Брокер при этом слушает только `127.0.0.1` — из интернета он недоступен
в принципе, не нужно ни открывать порт, ни настраивать фаервол.

### Шаг 6. Агент на ПК

```bash
.venv\Scripts\python.exe agent\main.py --broker https://имя.твой-tailnet.ts.net --token ТОКЕН
```

Либо положи токен в файл `.token` в корне проекта и запускай короче:

```bash
.\run-agent.ps1 https://имя.твой-tailnet.ts.net
```

В логе должно появиться `подключился к брокеру` и список устройств на
связи.

### Шаг 7. Телефон

1. Поставь **Tailscale** и войди тем же аккаунтом, что и на сервере.
   Если Google Play недоступен, официальный APK лежит в
   [релизах на GitHub](https://github.com/tailscale/tailscale-android/releases).
2. Включи тумблер VPN — в статус-баре появится иконка ключа.
3. Проверь связь, открыв в браузере `https://имя.твой-tailnet.ts.net/health`.
   Должен прийти JSON с `"ok": true`.
4. Открой приёмник: `https://имя.твой-tailnet.ts.net/?token=ТОКЕН`.
   Токен сохранится в браузере и сразу уберётся из адресной строки.
5. Разреши доступ к камере.
6. Меню браузера → «Установить приложение». Без установки Gesture Bridge
   не появится в системном меню «Поделиться».

## Проверка

Сквозной сценарий, по которому видно, что всё живо:

1. Выдели файл в проводнике на ПК, сожми кулак. В логе агента появится
   `заливаю <имя>`, в оверлее — «Захвачено».
2. На телефоне экран сменится на «покажи ладонь», камера поднимется.
3. Покажи раскрытую ладонь. Файл скачается.

Если второго устройства под рукой нет:

```bash
python tests/smoke_broker.py       # логика брокера, транспорт файлов, токены
```

```bash
python tests/smoke_gestures.py     # удержание жеста на дрожащей уверенности
```

```bash
python tests/smoke_capture.py      # захват: форматы буфера обмена
```

Ручные инструменты:

```bash
python agent/main.py --what        # что улетело бы прямо сейчас
```

```bash
python tests/fake_pc.py url        # отправить ссылку с несуществующего ПК
```

```bash
python tests/fake_pc.py text       # отправить текст
```

```bash
python tests/fake_pc.py file       # отправить файл
```

```bash
python tests/fake_pc.py watch      # слушать, что рассылает брокер
```

Адрес и токен для них берутся из переменных `BRIDGE_BROKER` и
`BRIDGE_TOKEN`.

## Настройка

### Ключи командной строки

**Агент** (`agent/main.py`):

| Ключ | По умолчанию | Зачем |
|---|---|---|
| `--broker` | `http://127.0.0.1:8787` | адрес брокера |
| `--token` | из `.token` или `BRIDGE_TOKEN` | токен доступа |
| `--name` | имя компьютера | как устройство видно остальным |
| `--camera` | `0` | номер камеры |
| `--selftest` | — | окно камеры с подписями, без брокера |
| `--what` | — | показать, что улетело бы сейчас |
| `--no-deep` | — | не использовать Ctrl+C как последний резерв |

**Брокер** (`broker/server.py`):

| Ключ | По умолчанию | Зачем |
|---|---|---|
| `--host` | `0.0.0.0` | интерфейс; за `tailscale serve` хватит `127.0.0.1` |
| `--port` | `8787` | порт |
| `--spool` | `$STATE_DIRECTORY/spool` или `./spool` | куда складывать файлы посылок |

### Пороги распознавания

`agent/gestures.py` для ПК и `receiver/app.js` для телефона — значения
одинаковые:

| Константа | Значение | Что делает |
|---|---|---|
| `ENTER_CONFIDENCE` | `0.55` | порог входа в удержание |
| `STAY_CONFIDENCE` | `0.35` | порог, ниже которого удержание рвётся |
| `LOST_GRACE` | `0.35` с | сколько прощается полная потеря руки |
| `SEEN_RECENTLY` | `0.12` с | рука должна быть видна в момент срабатывания |
| `HOLD_SECONDS` | `0.45` с | сколько держать жест |
| `COOLDOWN_SECONDS` | `1.5` с | тишина после срабатывания |

Если жест ловится, но срабатывает редко — снижай `ENTER_CONFIDENCE`.
Если срабатывает сам по себе — повышай его и `HOLD_SECONDS`.

### Поведение посылок

`broker/parcels.py`:

| Константа | Значение | Что делает |
|---|---|---|
| `FLYING_TTL` | `15` с | сколько ждём ладонь |
| `HOVERING_TTL` | `3600` с | сколько посылка висит в очереди |
| `DELIVERED_TTL` | `60` с | хранение доставленной без файлов |
| `DELIVERED_WITH_FILES_TTL` | `3600` с | запас на скачивание большого файла |

`broker/arbiter.py`:

| Константа | Значение | Что делает |
|---|---|---|
| `ARBITRATION_WINDOW` | `0.25` с | сколько брокер собирает ставки |
| `MIN_SCORE` | `0.05` | ниже — жест считается случайным |

`broker/blobs.py`:

| Константа | Значение | Что делает |
|---|---|---|
| `DEFAULT_MAX_FILE` | 1 ГиБ | предел на один файл |
| `DEFAULT_MAX_TOTAL` | 4 ГиБ | предел на всё хранилище |

`agent/main.py`:

| Константа | Значение | Что делает |
|---|---|---|
| `PALM_QUIET_AFTER_GRAB` | `2.5` с | агент игнорирует ладонь после своего захвата |

## Диагностика

### Телефон не ловит ладонь

Пока камера включена, поверх видео идёт строка отладки. По ней видно,
где именно обрывается цепочка:

| Что написано | Что это значит |
|---|---|
| `кадра нет: readyState=…, 0×0` | видео «играет», но кадров нет — переоткрой вкладку |
| `руки в кадре нет · 640×480 · CPU` | детектор не находит кисть: свет сзади, рука далеко или у края |
| `None 0.00 · рука 0.120` | кисть найдена, поза не опознана: разведи пальцы, держи ладонь к камере |
| `Open_Palm 0.52 · …` | не дотянул до `ENTER_CONFIDENCE` |
| `Open_Palm 0.65 · удержание 0%` | удержание не копится — порог входа высок для этой камеры |
| `сбой распознавания: …` | ошибка распознавателя, текст в строке |

Рядом с именами устройств внизу приписан делегат — `GPU` или `CPU`. Если
`CPU`, значит GPU не поднялся и мы откатились: это нормально, просто
медленнее.

### Телефон не открывает страницу

| Ошибка браузера | Причина |
|---|---|
| «Сервер не найден» | DNS: Tailscale на телефоне выключен или MagicDNS не применился |
| «Не удалось установить соединение» | имя разрезолвилось, но никто не ответил: в адресе лишний порт либо `tailscale serve` не настроен |

Адрес должен быть **без порта**: `tailscale serve` публикует брокер на
обычном 443, а `:8787` слушает только `127.0.0.1` на самом сервере.

### Служба не стартует

```bash
journalctl -u gesture-bridge -n 50 --no-pager
```

| Что в журнале | Причина |
|---|---|
| `не удалось подготовить папку для файлов` | в юните нет `StateDirectory=gesture-bridge` либо `--spool` указывает мимо `/var/lib/gesture-bridge` |
| ошибка про read-only файловую систему | не подхватился `BRIDGE_TOKEN`, брокер полез создавать `.token` |
| `activating (auto-restart)` в статусе | процесс падает сразу после запуска, смотри журнал |

### Агент ругается на непонятные сообщения

Почти всегда это рассинхрон версий: на сервере старый брокер. Проверь
одной командой — у нового есть маршрут `/blob`:

```bash
curl -s -o /dev/null -w '%{http_code}\n' -X PUT "https://имя.ts.net/blob?token=ТОКЕН&name=test" --data "x"
```

`200` — код свежий. `404` или `405` — на сервере старая версия, нужен
выкат.

### Жест срабатывает, но посылка возвращается к отправителю

Этого не должно быть: брокер отсеивает свои посылки до аукциона. Если
наблюдаешь — на сервере старая версия, см. выше.

## Протокол

WebSocket на `/ws?token=…`, обмен JSON-сообщениями с полем `t`.

### Клиент → брокер

| Тип | Когда | Поля |
|---|---|---|
| `hello` | при подключении | `name`, `device`, `caps` |
| `bid` | увиден жест | `role` (`grab`/`drop`), `signals`, опц. `id` |
| `grab` | создать посылку | `kind`, `payload`, `preview` |
| `claim` | забрать тапом из очереди | `id` |
| `cancel` | отменить свою посылку | `id` |
| `queue` | запросить висящую очередь | — |

`signals` — это `hand` (доля кадра), `conf` (уверенность), `idle`
(секунд без ввода). Счёт считает брокер, а не устройство, чтобы формула
была одна на всех.

### Брокер → клиент

| Тип | Что значит |
|---|---|
| `welcome` | подключение принято; несёт `me`, `peers`, `stack`, `queue` |
| `peers` | список устройств изменился |
| `you_grab` | ты выиграл аукцион захвата — снимай содержимое |
| `lost` | жест отдан другому устройству |
| `ignored` | жест слишком слабый |
| `grabbed` | твоя посылка создана |
| `pending` | для тебя есть посылка, поднимай камеру |
| `stack` | состав летящих посылок изменился |
| `deliver` | посылка твоя, вот содержимое |
| `taken` | посылку забрало другое устройство |
| `nothing_to_take` | брать нечего либо это твоя же посылка |
| `hovering` | посылка не востребована и упала в очередь |
| `queue` | содержимое висящей очереди |
| `cancelled`, `gone` | посылка отменена или истлела |
| `error` | текст в поле `reason` |

### HTTP

| Маршрут | Назначение |
|---|---|
| `GET /` | приёмник |
| `GET /share` | он же, цель Web Share Target |
| `GET /health` | живость; с токеном — подробности |
| `PUT /blob?name=…` | заливка файла, тело — сырые байты |
| `GET /blob/{id}` | скачивание файла |
| `GET /static/*` | статика приёмника |
| `GET /models/*` | модель распознавания для телефона |
| `GET /sw.js` | service worker (обязан лежать в корне) |

Типы посылок: `url`, `text`, `files`.

## Ограничения

- **Адресная строка через UI Automation** — работает с Chromium (включая
  Яндекс.Браузер) и Firefox, но ломается, если браузер перестроит своё
  дерево доступности. Надёжный путь — своё расширение.
- **Файл, открытый в приложении, но нигде не выделенный**, захватить
  нечем: Paint и просмотрщики не отдают путь, а Photos из Microsoft
  Store не отдаёт ничего. Выделение в проводнике и Ctrl+C работают,
  остальное требует адаптеров под конкретные программы.
- **Возврат буфера после Ctrl+C неполный**: возвращается только текст.
- **Картинка из буфера едет как BMP**, без сжатия. Для снимков экрана
  терпимо, для фотографий расточительно.
- **Телефон не может сам записать буфер или открыть вкладку** — браузер
  требует касания. Лечится нативным приложением.
- **На телефоне должна быть открыта вкладка приёмника.** Лечится тем же.
- **Netflix и прочий DRM** не отдадут позицию воспроизведения никогда.
